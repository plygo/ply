# Changelog

## v1.4.0

Repository and documentation split.

### Changed
- Module path moved from `github.com/Dziqha/ply` to `github.com/plygo/ply`.
- Source repository moved from `Dziqha/ply` to `plygo/ply`.
- Documentation moved to `plygo/website` and remains at
  `https://ply.web.id/docs`.
- `create-ply` now generates projects with the new module path.

### Migration
- Replace imports from `github.com/Dziqha/ply` with `github.com/plygo/ply`.
- Run `go mod tidy` after updating imports.

## v1.3.0

Tier 3 feature release.

### Added
- `websocket` package with upgrade helpers, text, binary and JSON messages,
  ping keepalive, origin checks, read limits and write serialization.
- `openapi` package that builds an OpenAPI 3.0 document from route metadata,
  including path conversion, operation overrides, components and security
  schemes.
- `oauth2` package with the authorization code flow, PKCE, refresh, userinfo,
  state, nonce and verifier helpers, plus extra authorization parameters.
- `oidc` package with provider discovery, JWKS caching and rotation, signed
  token verification, claims extraction and Bearer middleware.
- `grpcgateway` package for unary gRPC methods over JSON HTTP routes.
- Route metadata for OpenAPI generation and an `App.Routes()` accessor.
- Documentation for all Tier 3 packages.

### Changed
- `oauth2.Config.Refresh` now requires only `ClientID` and the token endpoint,
  not the authorization endpoint or redirect URL.
- `oauth2.Config.Exchange` rejects an empty authorization code.
- Added direct dependencies on `github.com/fasthttp/websocket` and
  `google.golang.org/protobuf`.

## v1.2.0

First Ply feature release after `v1.0.1`. The `v1.1.x` tags belong to the
deprecated TurboGo module and are not part of the Ply module path.

### Added
- `middleware.SecurityHeaders` for `nosniff`, frame, referrer, permissions,
  CSP, cross-origin opener and opt-in HSTS headers.
- `middleware.BodyLimit` with `Content-Length` and actual body checks.
- `middleware.Health` and `middleware.Readiness` for liveness and readiness
  probes.
- `middleware.SlogLogger` with method, path, status, duration, remote IP and
  request ID fields.
- `middleware.ETag` for strong response validators and `304` responses, plus
  `middleware.CacheControl` for cache directives.
- `middleware.NewMetrics` with Prometheus-compatible request counters and
  duration histograms, without a new dependency.
- `session` package with a cookie-backed manager, pluggable store and
  in-memory TTL store.
- Documentation for all new middleware and the session package.

### Changed
- Retracted `v1.0.0` through `v1.0.3` in `go.mod`.

## v1.0.0

First release as **Ply** (formerly TurboGo). Same code, same behavior,
same benchmarks; only the module path, package name and branding change.

### Changed
- Module path `github.com/Dziqha/TurboGo` -> `github.com/Dziqha/ply`.
- Package name `TurboGo` -> `ply`; call sites become `app := ply.New()`.
- Comparison harness updated to Fiber v3 3.6.1, Fiber v2 2.52.16 and
  Echo v5 5.4.4; benchmarks re-measured. No library change.
- CLI renamed from `create-turbogo` to `create-ply`.
- Documentation moved to `ply.web.id`; new brand assets.

### Notes
- No API changes beyond the package identifier: `App`, `Context`,
  middleware and router behavior are identical.
- TurboGo `v1.1.2` is the final release of the old module and only adds
  a deprecation notice pointing here. Existing TurboGo versions remain
  fetchable from the Go module proxy.

Dependency-only release; no public API changes.

### Changed

  module's `go` directive rises from 1.25 to **1.26**; CI, docs and the
  Dockerfile follow.
- validator `10.20.0` -> `10.30.6`, jwt `5.2.2` -> `5.3.1`,
  fatih/color `1.18.0` -> `1.19.0`, testify `1.11.1` -> `1.12.1`.

### Notes
- The bench comparison harness is now tracked by dependabot (`/bench`
  module), so engine upgrades cannot silently hide from the benchmarks.
- The bench workflow now also runs on `main`.
- Framework overhead was re-measured on fasthttp 1.77 (see the benchmarks
  page): the layer remains thinner than a bare path-plus-switch handler.

## v1.1.0

### Performance
- Compiled-switch route dispatch with a radix fallback, backed by a
  differential fuzz test against the original lookup (0 mismatches over
  random paths and methods).
- Zero-allocation path params: up to 8 values land in inline context slots,
  with an overflow map only for fallback matches.
- Skip fasthttp's URI parse and path normalization when it provably cannot
  change the path (92ns -> 14ns per request), with a 50k-target differential
  test proving equivalence and a fallback for everything else.
- Framework overhead for a param route fell from 255ns to 155ns in-process,
  now below a bare path-plus-switch handler (166ns).

### Added
- `app.Test(*http.Request) *http.Response`: run the full application
  (router, middleware, recovery, bindings) in-process without opening a port.
- `app.Handler()` now caches its closure, so repeated callers no longer
  rebuild the routing table on every call.

### Changed
- `App.Handler()` freezes routing once and relies on lazy recompilation when
  routes are added later.
- Benchmark and comparison documentation rewritten with methodology, medians,
  min-max spread and honest caveats.
- `v1.0.0` through `v1.0.3` are retracted; upgrade to `v1.1.0`.
